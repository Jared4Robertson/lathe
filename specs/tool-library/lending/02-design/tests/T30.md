Planned, not written yet. The router stops buffering a body at 64 KB and answers 413 `body_too_large`, but it keeps the connection alive, so Node goes on reading and discarding the rest of the body; a client that never stops sending holds the connection open. Whether the 413 should also close the connection (`Connection: close`) is to be settled with the router change it needs, and the test waits for that so it proves the final behaviour rather than today's.

When written, it sends `POST /tools/{toolId}/damage` with a note of about 100 KB and expects 413 `body_too_large` with the tool still `good`; sends a body just under 64 KB and expects it to be read; and, if the connection is to close, checks that it does.
