Jared reads a domain's Technical specification and Test plan in groups instead of two long lists. Technical specification lists the domain's layers in order, each holding its components, then the components outside any layer. Test plan groups each test by what it proves: acceptance tests by capability and use case, then domain rule, pattern and interaction tests, then engineering checks. The side nav, the domain page, the group pages and the graph all show the same groups, and the graph's trail names what he has visited.
